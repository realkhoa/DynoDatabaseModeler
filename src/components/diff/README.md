# Visual Schema Diff & Interactive Safe Migration Modal (`src/components/diff`)

## 1. Overview & Purpose
The `src/components/diff` module provides an interactive review and execution dialog for database schema synchronization in **DynoDbModeler**. It bridges the visual ERD diagram workspace with the target database dialect engines (SQLite, PostgreSQL, MySQL, SQL Server) by displaying:
- A structural change hierarchy detailing created tables, dropped tables, added columns, dropped columns, altered column definitions, and foreign key modifications.
- Telemetry banners highlighting destructive changes (table drops, column drops, or narrowing alterations) to prevent accidental data loss.
- An embedded Monaco Editor displaying formatted SQL DDL statements generated for the active dialect, with live editing and clipboard copying capabilities.
- Transactional migration execution triggers reporting real-time execution duration and statements count.

---

## 2. Prerequisites & Dependencies
- **React 19 / TypeScript 5.7+**: Component rendering and type safety.
- **`@monaco-editor/react`**: Embeds Monaco SQL code editor with syntax highlighting and line numbers.
- **`lucide-react`**: TablePlus minimalist icons (`AlertTriangle`, `Check`, `Copy`, `X`, `Loader2`, `ShieldAlert`, `FileCode`).
- **`src/types/database.ts`**: Core `SchemaDiff`, `TableSchema`, and `ColumnSchema` models.
- **Tauri IPC (`src/api/ipc.ts`)**: Invokes backend DDL generation (`cmd_generate_ddl`) and transaction execution (`cmd_execute_migration`).

---

## 3. Component Props & API Reference

### `DiffModalProps`
| Property | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `isOpen` | `boolean` | Yes | Controls whether the migration review modal overlay is visibly rendered. |
| `diff` | `SchemaDiff \| null` | Yes | Structural schema difference between the pristine database schema and desired canvas design. |
| `generatedDdl` | `string[]` | Yes | Array of dialect-specific SQL DDL statements generated by the Rust backend engine. |
| `onClose` | `() => void` | Yes | Dismissal callback invoked when user clicks Cancel or the header Close button. |
| `onExecute` | `(statements: string[]) => Promise<void>` | Yes | Async callback invoked to execute the parsed/edited migration statements in a transaction. |

## 4. Usage Examples

### Integration within React Application Shell
```tsx
import React, { useState } from 'react';
import { DiffModal } from './components/diff/DiffModal';
import { api } from './api/ipc';
import type { SchemaDiff } from './types/database';

export const MyDatabaseWorkspace: React.FC = () => {
  const [isDiffOpen, setIsDiffOpen] = useState(false);
  const [diff, setDiff] = useState<SchemaDiff | null>(null);
  const [ddl, setDdl] = useState<string[]>([]);

  const handleOpenSync = async () => {
    const computedDiff = await api.computeDiff(liveSchema, currentSchema);
    const statements = await api.generateDdl(computedDiff);
    setDiff(computedDiff);
    setDdl(statements);
    setIsDiffOpen(true);
  };

  const handleExecute = async (statements: string[]) => {
    const report = await api.executeMigration(statements);
    if (!report.success) throw new Error(report.error_message || 'Migration failed');
    await refreshSchema();
  };

  return (
    <div>
      <button onClick={handleOpenSync}>Review & Sync</button>
      <DiffModal
        isOpen={isDiffOpen}
        diff={diff}
        generatedDdl={ddl}
        onClose={() => setIsDiffOpen(false)}
        onExecute={handleExecute}
      />
    </div>
  );
};
```

## 5. Output Structure & Schema
The visual tree categorizes differences into semantic buckets with distinct color schemes:
- **`tables_to_create`**: `+ Create Table: <name>` (Emerald Green: `#20c997`).
- **`tables_to_drop`**: `- Drop Table: <name>` (Destructive Red: `#e05252`).
- **`columns_to_add`**: `+ <table>.<column>` (Blue: `#3a82f7`).
- **`columns_to_drop`**: `- <table>.<column>` (Destructive Red: `#e05252`).
- **`columns_to_alter`**: `~ <table>.<column>` (Amber: `#f59e0b` or Red: `#e05252` if marked `is_destructive`).
- **`foreign_keys_to_add`**: `+ FK: <table>.<column> -> <target_table>.<target_column>` (Emerald Green: `#20c997`).
- **`foreign_keys_to_drop`**: `- Drop FK: <table>.<constraint_name>` (Destructive Red: `#e05252`).

## 6. Troubleshooting & Edge Cases
- **Missing or Empty DDL**: If no structural differences are detected, the editor displays an empty state and the "Execute Migration" button is disabled.
- **Custom SQL Parsing**: SQL statements edited in the Monaco editor are split by semicolon delimiter (`;`), trimmed, and validated before submission.
- **Transaction Rollback**: Any failure during multi-statement execution automatically rolls back the entire batch via backend driver transaction protection, returning a descriptive error toast in the UI.
